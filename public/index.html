Research system

A crash is the start of the argument.

Findings enter the portfolio only after reachability, current-version, native-impact, control, duplicate, and attribution checks.

  1. 01

    Read before fuzzing

    Map untrusted input to ownership, bounds, and lifecycle invariants. Compare the path against upstream harness coverage.

    source audit
  2. 02

    Model valid state

    Retain authentication, protocol ordering, object graphs, and public API sequences long enough to reach deep code.

    stateful harness
  3. 03

    Prove a real consequence

    Pair sanitizer diagnostics with native builds, matched controls, repeated trials, and application-visible effects.

    impact gate
  4. 04

    Check novelty and credit

    Search current source, history, advisories, and trackers. Retire exact duplicates without claiming original discovery.

    novelty gate
  5. 05

    Coordinate the fix

    Send minimal claims, portable reproduction, version evidence, and a tested fix direction through the project’s chosen route.

    disclosure

Research integrity

Strong claims need stronger evidence.

01

No CVE inflation

A CVE counter changes only when a public record exists. Requests and acknowledgements are tracked separately.

02

No duplicate credit

Independent rediscoveries stay visible as validation work and name the original public fix or finder.

03

No speculative RCE

Memory corruption, disclosure, denial of service, and code execution are reported as distinct evidence levels.
